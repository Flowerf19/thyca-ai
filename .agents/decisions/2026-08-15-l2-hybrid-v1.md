# Decision — L2 hybrid retrieval is part of v1

## Decision

Thyca v1 includes L2 lexical memory retrieval (`memory_search`: FTS5 + trigram). Embedding / `semantic=true` / vector / RRF was cancelled 2026-09-16 — not frozen, not part of v1. The agent remains the retrieval controller: the tool does not silently escalate a miss.

Markdown under `~/.thyca` remains the source of truth. SQLite is a derived index. Daily files are indexed after they close; canonical files (`SOUL.md`, `USER.md`) are always indexable and are not assigned a daily date. `MEMORY.md` removed 2026-08-25 — see `2026-08-25-drop-memory-md.md`. Search results are leaf-level evidence with a session pointer; full session context is fetched only through `memory_get(session_id)`.

`memory_remember` is the only tool writer for `~/.thyca` memory files. `write` and `edit` must reject paths under `~/.thyca`; writes outside that home data remain allowed by the v1 tool contract. Read-only tool calls may run concurrently; mutating calls are serialized per resource.

## Consequences

- The old FTS-only, one-file-per-row description in `thyca-harness-v1.md` is superseded by the L2 plan and must not remain an active implementation contract.
- v1 is lexical-only. Do not reintroduce embedding, sqlite-vec, ONNX, or Harrier.
- Embedding identity / model-install contracts are cancelled with the semantic path.

## Non-goals

No ANN index, vector database, background watcher, automatic memory prefetch, or third-party memory MCP is added for v1.
