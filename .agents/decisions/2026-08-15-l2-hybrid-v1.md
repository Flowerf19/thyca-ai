# Decision — L2 hybrid retrieval is part of v1

## Decision

Thyca v1 includes L2 hybrid memory retrieval. `memory_search(semantic=false)` runs lexical retrieval (FTS5 + trigram); `semantic=true` runs lexical plus vector retrieval and fuses candidates with RRF. The agent remains the retrieval controller: the tool does not silently escalate a lexical miss to semantic search.

Markdown under `~/.thyca` remains the source of truth. SQLite is a derived index. Daily files are indexed after they close; canonical files (`SOUL.md`, `USER.md`, `MEMORY.md`) are always indexable and are not assigned a daily date. Search results are leaf-level evidence with a session pointer; full session context is fetched only through `memory_get(session_id)`.

`memory_remember` is the only tool writer for `~/.thyca` memory files. `write` and `edit` must reject paths under `~/.thyca`; writes outside that home data remain allowed by the v1 tool contract. Read-only tool calls may run concurrently; mutating calls are serialized per resource.

## Consequences

- The old FTS-only, one-file-per-row description in `thyca-harness-v1.md` is superseded by the L2 plan and must not remain an active implementation contract.
- v1 needs the lexical path even when the embedding model is unavailable. Semantic retrieval must return a warning plus lexical results rather than crash.
- Embedding identity is part of the index key. Changing provider, model, dimension, or query-prompt revision invalidates old vectors.
- The implementation must include an executable model availability/install contract; `onnxruntime` and `tokenizers` alone do not provide Harrier weights.

## Non-goals

No ANN index, vector database, background watcher, automatic memory prefetch, or third-party memory MCP is added for v1.
